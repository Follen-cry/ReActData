## 2. 发现

### 2.1 训练随机性（数据顺序）远大于协议里的 δ

完全相同的 baseline 配方，只换数据顺序（c000、c007、c011、c012、c014），dev 分数分别为 0.4384、0.4430、0.4337、0.3914、0.4221：
- 极差约 0.05，标准差约 0.02；
- 两次独立训练之差的标准差约 0.03。

这个噪声是 agent 在 c011–c014 中自己测出来的，它在 c013 的说明里主动纠正了先前把噪声估为 ±0.005 的说法。

协议里的 δ（0.047）只来自同一模型在不同生成 seed 下的差异，CI 只对 dev 样本做重采样，两者都没有计入训练随机性。直接证据是：c012 是 baseline 的原样重复，它相对 c000 的 CI 却完全落在 0 以下。

结论：
- 表中“显著更差”的候选（c006、c008、c009、c010、c013），其差异大多可以被训练噪声解释，不能作为它们有害的证据。
- r1 中“额外帧有害”的结论（c002 −0.079），也需要按这个噪声重新审视；它的幅度大于 baseline 重复的极差，但只有一次训练。

### 2.2 选择规则在后续搜索中有误选风险

选择规则是：D ≥ δ 且 CI 下界大于 0 时选该候选。
- 如果两次训练之差的标准差约 0.03，单个纯噪声候选越过 0.047 的概率大约是 5%–6%；在剩余几十个候选里取最大值，出现一个“运气好”的候选并被选中的概率不低。
- P3 只用单个训练 seed 在 test 上重训，只能部分识别这种误选。

### 2.3 agent 把候选预算用在了重复实验上

在已知结果都在噪声范围内、又没有正向假设的情况下，agent 开始用候选名额做 baseline 重复：最近 8 个候选里有 5 个只改了一个 shuffle salt。
- 这在科学上是合理的，它是在估计噪声底；但这本应由 Runner 在搜索前完成。
- “重复程序不训练”的规则只比较代码、模板、配置的哈希，只改 salt 的候选哈希不同，所以没有被拦下。

### 2.4 父程序选择在追逐噪声

工作区规则是“从 dev 分数最高的有效程序起步”。c007 只是运气较好的一次 shuffle，却成了 c009 之后所有候选的起点。

### 2.5 反馈利用不足

- **轮内看不到结果**：2 × 2 结构下，每轮第 2 个候选看不到第 1 个的结果，agent 在 c006、c008、c010、c012、c014、c016 的说明里都写了“results weren't available yet”。
- **没有用到 probe**：内层 probe 和 analysis 的可改写性没有被利用，“训练中反馈”这一研究问题基本没有被测试到。
- **会话很短**：agent 每次会话约 20–25 秒，只能读报告，不能在数据上做分析。

### 2.6 基础设施运行正常

截至快照时：
- 没有任务失败、候选被拒、重复候选或会话接续失败；
- `--resume` 会话链一直有效，agent 记得 r1 以来的全部历史；
- 磁盘峰值约 15 GB，远低于 60 GB 上限；
- 每轮约 27 分钟。

## 3. 修改建议（需要新协议版本）

1. **搜索前估计训练噪声**：Runner 先用 3–4 个不同的数据 seed 重复训练 baseline，用“候选减 baseline 重复”的差异分布来定 δ，并把噪声估计写进 agent 的报告。
2. **重新分配算力**：生成噪声相对较小，dev 改为 1 个生成 seed；省下的算力用于对入围候选多训练 2–3 个数据 seed。选择依据改为多 seed 均值的差，其不确定性同时计入训练和样本两部分。
3. **加入确认阶段和多重比较控制**：搜索结束后，dev 排名前 k 的候选用新的数据 seed 重训确认，再做选择；对比较次数做校正，或者只使用确认阶段的数据来选择。
4. **禁止用候选名额做重复实验**：只改随机 salt 或 shuffle 的候选视为重复程序；需要重复实验时，由 Runner 统一提供（例如每轮一个 baseline 重复），并单独计入预算。
5. **父程序规则**：改为固定从 baseline 起步，或者按多 seed 均值选最优，或者让 agent 显式指定父程序并说明理由，避免追逐单次运行的运气。
6. **轮次结构**：改为每轮 1 个候选（4 × 1 式的串行），或让同轮第 2 个候选等第 1 个的结果，使每次修改都能看到上一次的反馈。按当前耗时，50 个串行候选约需 21 h，预算要相应调整。
7. **鼓励检验反馈问题**：如果研究重点是“训练中反馈是否有价值”，可以要求一定比例的候选实现 analysis 或 probe 反馈，并在报告中提供 probe 用法的示例。
8. **（可选）增强 agent 的分析能力**：在 /input 中提供逐项 dev 结果在 baseline 重复之间的方差，以及各候选的逐行训练统计，使 agent 能区分信号和噪声。
