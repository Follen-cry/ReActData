# reactdata-v1 协议 v3（2026-10-26，已实现，尚未运行）

依据：[r1.1 中途审查](2026-10-26_reactdata-v1_r1.1_midrun-review.md) 第 3 节的建议，以及研究者的决定“改为 10 轮 × 1 个候选，暂不开新 run”。

| 建议 | v3 中的实现（`reactdata-v1/protocol_v3.yaml`、`runner/`） |
|---|---|
| 1. 搜索前估计训练噪声 | P1 用 5 个 run seed（1000–1004）重复训练 baseline，得到 sd_train，δ 取 sd_train；噪声数值写进 agent 的报告 |
| 2. 重新分配算力 | dev 只用 1 个生成 seed（生成噪声 SE 约 0.007，远小于训练噪声 sd 约 0.02） |
| 3. 确认阶段与多重比较 | 筛选分数前 3 名用 4 个 seed（1001–1004）重训，与相同 seed 的 baseline 重复配对比较；SE² = 2·sd_train²/R + SE_item²；对 3 个候选做 Bonferroni 校正；需要 D ≥ δ 且 CI 下界 > 0 才选中，否则选 baseline |
| 4. 禁止只改 salt 的候选 | `databuilder.py`、`analysis.py`、`text_templates.yaml` 都与已有程序相同即视为重复：不训练，但占用名额 |
| 5. 父程序规则 | 工作区从 agent 自己最近的有效候选起步，形成迭代谱系；agent 也可以从 /input 里复制任意早期程序 |
| 6. 轮次结构 | 10 轮 × 1 个候选，串行，每个候选都能看到之前全部结果 |
| 7. 鼓励探索与反馈 | `BUILDER_AGENT_v3.md`：删掉“不确定时优先简单程序”；告知噪声大小；要求每个候选检验一个预期效果 ≥ 约 0.05 的假设；列出可用的杠杆（包括 analysis 与 probe） |
| P3 | 选中的程序与 baseline 各用 3 个正式 seed（2000–2002）重训，在 test 上用同一统计量比较 |

- **噪声的实测依据**：同一 baseline 配方 5 次训练的 dev 分数为 0.4384 / 0.4430 / 0.4337 / 0.3914 / 0.4221，sd = 0.021（3 个生成 seed）或 0.025（1 个生成 seed）。把其中 2 次当“候选”、另 2 次当“baseline”做零差异检验，D = +0.032，新方法给出的 CI [−0.021, +0.084] 正确地覆盖了 0。按这个噪声水平，确认阶段大约能检出 ≥ 0.05 的效果。
- **测试**：`tests/test_v3_flow.py`（CPU，用假执行器和假 agent）10 项检查全部通过。测试中发现并修复了一个 bug：v3 改用 `screen_seed` 后，一处提示文本仍在读旧键名。GPU smoke 尚未运行。
- **预计耗时**：P1 约 0.8 h，搜索约 2.8 h，确认约 1.6 h，P3 约 1.1 h，合计约 6.5 h（墙钟预算 12 h）。

## 未纳入 v3、需要研究者决定的方向

1. **扩大动作空间**：允许中间帧作为训练目标（配合写明时间的文本），即预测中间状态、做任务分解。这是视频最可能真正起作用的方式，但会改变首轮“目标恒为末帧”的决定。
2. **限制 clip 数量**：例如 64 / 256 / 1,600 个 clip，训练步数不变。在 clip 稀缺、baseline 只能反复使用同一批端点的条件下，过程帧额外提供的监督才可能显出价值。
3. **增强 agent 的分析能力**：例如提供可在沙箱里读取训练帧和逐项结果的分析工具，或者允许它申请廉价的诊断任务。
